# Build the motion airframe, not the pilot

**An open, agent-first character animation package is feasible in October 2026, and its central niche is empty: no vendor, engine or open project ships a 3D motion format built for language models to read and edit, a display-free motion verifier, or animation-specific agent tools beyond a few community engine bridges, while the owner's repositories have already prototyped all five proposed parts, though never in one place.** Readiness is uneven. The readable key-pose format, the headless checks and the tool interfaces are proven enough to standardize now, but the runtime's hard core (retargeting onto arbitrary skinned skeletons, foot contact, root motion, blend graphs) is unsolved in every predecessor and absent from three.js. The self-growing, AI-contributed library is the weakest leg, because legally clean motion data is scarce, the only commercially clean open generator (NVIDIA's Kimodo) sits under a license NVIDIA can rewrite, and open AI-contribution channels elsewhere have been flooded with spam and malware. The evidence therefore favors one shape: a versioned specification, a curated and provenance-tracked library, a conformance suite, and a deterministic runtime and verifier, with generative models plugged in as interchangeable suppliers, the airframe rather than the pilot. It should not train models, build an editor, run video capture, operate an open upload portal, or rebuild what Unreal and Unity already ship. Its largest risks are less technical than they look: the first outside agent handed the predecessor engine used none of its 325 clips, the clip codec is headed for its third implementation and has already forked under one version number, and license errors have already crept into the predecessor's data.

## Every animation pipeline in 2026 still ends in an opaque file

The interchange formats an agent meets were built for applications, not readers. **glTF 2.0** stores keyframes in binary accessors bound to nodes by array index, carries no humanoid semantics and, in a Babylon.js maintainer's words, offers "no way to store the desired animation behavior (such additive)" ([glTF 2.0 specification](https://raw.githubusercontent.com/KhronosGroup/glTF/main/specification/2.0/Specification.adoc); [Babylon.js forum](https://forum.babylonjs.com/t/model-disapears-on-additive-animation-group-glb-export/30199)). **VRM Animation** is the best open humanoid clip format, complete at 1.0 and playable on any VRM avatar through a three.js loader updated in July 2026, yet it is still per-frame quaternions in a glTF buffer, with no IK goals, contacts, layers or events ([VRMA specification](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm_animation-1.0/README.md); [npm registry](https://registry.npmjs.org/@pixiv/three-vrm-animation)). BVH is text but semantically flat, one row of channel values per frame with no naming standard, and Spine's JSON, the best existing model of an editable skeletal clip, is 2D and requires every user to hold an editor license ([GameDev.net](https://gamedev.net/tutorials/programming/general-and-gameplay-programming/bvh-file-loading-and-displaying-r3295); [Spine Runtimes License](https://en.esotericsoftware.com/spine-runtimes-license)). The format survey behind this report found no open, LLM-oriented 3D skeletal motion format with humanoid semantics, and the one paper that had GPT-4 keyframe rigged characters had to invent its own text encoding, keeping only keyframes and "truncating floating-point numbers to a single significant figure" ([arXiv 2310.17838](https://arxiv.org/pdf/2310.17838)).

Commercial tools close the loop only as far as a download. Uthana's GraphQL API, which also supplies Unity AI's animation generator, takes an agent from prompt to retargeted clip end to end but returns FBX, GLB or BVH; Unity's generator saves `.anim` assets, and Cascadeur's free tier exports only `.casc` ([Uthana API blog](https://uthana.com/blog/how-uthanas-api-speeds-up-text-to-motion-animation); [Unity third-party AI terms](https://unity.com/legal/third-party-ai-terms); [Unity docs](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.6/manual/Animation/animation-create.html); [Cascadeur plans](https://cascadeur.com/plans)). The engines' new agent bridges skip motion entirely. Unity's official MCP server (beta since May 2026), Epic's experimental Unreal MCP in UE 5.8 (loopback-only, unauthenticated, serial on the game thread) and Roblox Studio's built-in server with roughly 27 tools expose **no clip, keyframe, retargeting or animation-graph operations**, and Blender's community server, at 30.4k stars the most popular 3D MCP, has none either and has the agent write Python instead ([Unity blog](https://unity.com/blog/unity-ai-mcp-how-to-get-started); [Epic docs](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor?lang=en-US); [Roblox docs](https://create.roblox.com/docs/studio/mcp); [blender-mcp](https://github.com/ahujasid/blender-mcp)). What transfers from them are observation tools, such as blender-mcp's `look` with an animation frame strip and Roblox's camera-parameterized `screen_capture`, and none of them returns a single motion metric.

Four shifts in 2025–26 make an open package timely. **Commercially usable open generation now exists**: NVIDIA released Kimodo in March 2026 with Apache-2.0 code and weights it calls "ready for commercial use," steerable by text plus keyframe, joint and path constraints ([Kimodo README](https://github.com/nv-tlabs/kimodo); [Kimodo model card](https://huggingface.co/nvidia/Kimodo-SOMA-SEED-v1.1)). **Agent interfaces standardized**: MCP moved to the Linux Foundation's Agentic AI Foundation in December 2025 with more than 10,000 public servers, and Agent Skills became an open standard that now lists 46 client products ([Anthropic](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation); [agentskills.io](https://agentskills.io)). **Vendor attrition made self-hosting a requirement**: RADiCAL closed its portal on July 6, 2026; Ready Player Me shut down on January 31, 2026 without letting users export their avatars; Meshcapade was absorbed by Epic; DeepMotion narrowed its API to "verified partners"; and Uthana stopped selling subscriptions in August 2026 ([CG Channel](https://www.cgchannel.com/?p=175200); [Genies](https://genies.com/blog/ready-player-me-shutdown); [80.lv](https://80.lv/articles/ai-motion-capture-startup-meshcapade-now-part-of-epic-games); [DeepMotion](https://deepmotion.com/saymotion-api); [Uthana pricing](https://uthana.com/pricing)). **Capital is chasing generation, not infrastructure**: Tripo raised roughly $800M across three 2026 rounds while animation-specific startups raised rounds of $4.3M to $10M, so an open infrastructure project competes with no one for that money ([Pulse 2.0](https://pulse2.com/tripo-ai-raises-over-150-million-in-series-a3-financing/amp/); [DealStreetAsia](https://www.dealstreetasia.com/?p=493956); [Pulse 2.0 on Uthana](https://pulse2.com/uthana-4-3-million-raised-to-transform-3d-character-animation-with-genai); [Cartoon Brew](https://www.cartoonbrew.com/tech/jeffrey-katzenberg-backed-ai-animation-software-cartwheel-raises-10-million-247264.html)).

Research supports the package's premise without proving it. Language models handle motion best through compact, quantized, semantically named descriptors: CoMo's body-part "pose codes" let an LLM "directly intervene" in edits, and SayTap's foot-contact patterns solved 10 more of 30 quadruped tasks than alternative interfaces ([CoMo](https://arxiv.org/abs/2403.13900); [SayTap](https://arxiv.org/abs/2306.07580)). Agents succeed with code-first animation when a deterministic checker closes the loop: MoVer's verifier feedback lifted correct LLM motion graphics **from 58.8% to 93.6%** (with up to 50 repair rounds), TheoremExplainAgent reached 93.8% success on Manim videos, and Remotion, which ships twelve official agent skills, draws about 2.08 million npm downloads a week ([MoVer](https://www.arxiv.org/abs/2502.13372); [TheoremExplainAgent](https://arxiv.org/abs/2502.19400); [Remotion skills](https://www.remotion.dev/docs/ai/skills); [npm](https://api.npmjs.org/downloads/point/last-week/remotion)). But no public benchmark measures frontier models authoring or editing skeletal keyframes, and BlenderGym found that "even the strongest" vision-language systems struggle with 3D edits Blender users find easy ([BlenderGym](https://arxiv.org/abs/2504.01786v1)). The central bet is plausible and unmeasured, which makes measuring it the package's first job.

## Four repositories built every part, but never one package

The origin repository, my-3d2dge, produced the most valuable artifact: **readable key poses**. A key is a time plus up to 14 named fields of whole numbers: pelvis height as a percentage of standing hip height, torso turn, lean and tilt in degrees, and each limb as a direction plus a bend and a twist, which is an IK parameterization rather than a dump of joint angles ([readable.js](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/src/mocap/readable.js#L25-L38)). A 14-line legend rides in every file, and by this study's token counts it costs about 440 tokens, a key about 150, and the 325 curated clips (6,469 keys, 693 seconds of motion) roughly 970k; set-level mean errors against the source capture run **13.9 to 17.8 mm**, with worst cases up to 286 mm ([my-3dge PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L288-L297)). The format won a measured bake-off on 46 clips at 31 KB gzipped against 118 KB for every frame, and was the only candidate "a model can read" ([MOCAP.md](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/docs/MOCAP.md?plain=1#L302-L314)). Its codec carries fixes for failures it actually hit: bends stored in degrees because "storing reach as a fraction moved a nearly straight knee 56 mm per rounding step," and a carried twist reference because an earlier one "flipped, and in-betweens put the elbow on the wrong side" ([MOCAP.md](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/docs/MOCAP.md?plain=1#L279); [readable.js](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/src/mocap/readable.js#L106-L111)). Engines reached the same size-independence trick on their own: Godot normalizes position tracks by hips height, Babylon.js scales root displacement proportionally, and VRMA stores rotations plus hips translation only ([Godot docs](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html); [Babylon.js forum](https://forum.babylonjs.com/t/introducing-animation-retargeting/62547)).

Adoption proved the format travels. shardfall, a Rust and wgpu engine, kept it "as is so clips move between the engines" and ported the importer step for step, verifying **all 119,432 numbers of the Mesh2Motion set and all 104,101 of the CMU set identical** to the JavaScript original and regenerating all 2,548 CMU ledger rows exactly ([shardfall HISTORY.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L366-L373); [lines 445–449](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L445-L449)). That parity required emulating V8's numerics, from fdlibm trigonometry to JavaScript's rounding and `toFixed`, and about 7,500 lines of Rust ([HISTORY.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L441-L444)). shardfall then added what an agent workflow needs: a loop `speed` for stride matching, strike times measured from the motion, a `clips` tool that returns legend, text, fit, strike time and license, and an Animation Studio whose every edit returns a `revision` the next edit must echo as `if_revision` ([HISTORY.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L460-L465); [clips.rs](https://github.com/michaelcrosato/shardfall/blob/a9ca003/crates/pav_core/src/clips.rs#L496-L550); [anim_tools.rs](https://github.com/michaelcrosato/shardfall/blob/a9ca003/crates/pav_tools/src/anim_tools.rs#L749-L820); [ANIMATION_STUDIO.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/ANIMATION_STUDIO.md?plain=1#L185-L189)). my-3dge plans a third implementation in TypeScript and declines shardfall's port in so many words ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L770)). riftlight never adopted the format, yet holds the strongest runtime ideas: a gait generator with "zero foot slide by construction," foot placement with a lock mode, clip metrics that flag sliding against clip speed, and a semantic `Poser` that animates any generated body from one template ([riftlight ANIMATION.md](https://github.com/michaelcrosato/riftlight/blob/f3693fc/docs/ANIMATION.md?plain=1#L234-L244); [metrics](https://github.com/michaelcrosato/riftlight/blob/f3693fc/docs/ANIMATION.md?plain=1#L69-L79); [poser.ts](https://github.com/michaelcrosato/riftlight/blob/f3693fc/src/riftlight/monsters/anim/poser.ts#L5-L11)).

The agent interface pattern is proven too. Depthward (my-3d2dge-2) defines each tool once in a typed registry that feeds a browser console, a CLI, a dependency-free stdio MCP server and WebMCP, deriving schemas, examples and "Did you mean" errors from that single definition ([registry.ts](https://github.com/michaelcrosato/my-3d2dge-2/blob/c8295dc/src/agent/registry.ts#L107-L161); [mcp-server.mjs](https://github.com/michaelcrosato/my-3d2dge-2/blob/c8295dc/tools/mcp-server.mjs)). Yet none of its 46 tools lists, inspects, edits or checks a clip, and the simulation sees only each clip's duration, loop flag and root speed ([assets.ts](https://github.com/michaelcrosato/my-3d2dge-2/blob/c8295dc/src/render/assets.ts#L33-L35)).

The failures teach as much. **Discoverability failed first.** Handed only the origin's one-file engine, an outside agent ("GPT-6 Astra Pro") built an isometric, Assassin's Creed-style climbing and stealth game in about 50k output tokens without touching the motion store, although the store held `ClimbUp_1m_RM`, Ledge Hang, `Walk_Stealth` and Roll; it bypassed the melee helpers and read the 150k-token source to find 28 undocumented members ([HANDOFF](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/docs/HANDOFF-VESPER-FEEDBACK.md?plain=1#L54-L77); [FEEDBACK-LOG](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/docs/FEEDBACK-LOG.md?plain=1#L48-L49)). The store sat outside the file the agent received, and the benchmark designed to measure such behavior was proposed and never run ([HANDOFF](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/docs/HANDOFF-VESPER-FEEDBACK.md?plain=1#L312-L328)). **Verification had blind spots.** The character sheet reports no foot sliding because its slide check runs only on idle and its "run" state runs in place; stepping the procedural gait headless for this study measured each foot grounded only about a quarter of the time at walking speed (a real walk is near 60%) and planted feet sliding at **11–28% of body speed** ([ed-sheet.mjs](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/tools/ed-sheet.mjs#L116-L122); [18-characters.js](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/src/emberdeep/18-characters.js#L83); [gait code](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/engine/my-3d2dge.js#L1932-L1934)). **Governance was weak.** shardfall's reader never checks `format` and ignores unknown clip fields; it added `speed` while keeping `"format": 1`, the same fields my-3dge calls format 2; and `QUATERNIUS` names 88 Rigify-sourced clips in one repository and 102 Unreal-rig clips in another, both at format 1 ([clips.rs](https://github.com/michaelcrosato/shardfall/blob/a9ca003/crates/pav_core/src/clips.rs#L153-L160); [PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L3573-L3597); [origin set](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/src/mocap/sets/quaternius.js#L21-L22); [shardfall set](https://github.com/michaelcrosato/shardfall/blob/a9ca003/anim/quaternius.json)). Hit timing lives outside the clips: riftlight's docs warn "move a hit in a clip and move it there too," and Depthward's hit fractions are typed by hand ([GAME.md](https://github.com/michaelcrosato/riftlight/blob/f3693fc/docs/GAME.md?plain=1#L169-L170); [skills.ts](https://github.com/michaelcrosato/my-3d2dge-2/blob/c8295dc/src/content/skills.ts#L158-L180)). **Retargeting stayed narrow.** The origin retargets only onto its own 15-joint drawn rig, Depthward only between identically named skeletons, correcting bind-pose differences of up to about 12°, and shardfall's decoder holds limbs within 9° while a curled spine drifts up to about 14° and a captured levitating idle "reads as a crouch on this rig" ([mocap.js](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/src/mocap/mocap.js#L165-L262); [retarget.ts](https://github.com/michaelcrosato/my-3d2dge-2/blob/c8295dc/src/render/retarget.ts#L4-L11); [HISTORY.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L501-L507); [lines 209–210](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L209-L210)). **Licensing drifted.** The CMU record omits CMU's no-resale clause while the agent manual promises "every clip is free to use" ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L301); [agent manual](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/engine/my-3d2dge-agent.js#L329-L331)).

The pattern across five repositories is plain: **what moved between engines was data, specification and golden vectors, and the code was rewritten every time.** The package's real product is therefore a standard with its evidence (a spec, curated data and a conformance suite) plus one reference runtime. Two of the three conformance tiers already exist: bit-exact encoder parity on shardfall's fixtures, and semantic parity on a different body within a per-limb angle, as in shardfall's 9° test ([motion.rs](https://github.com/michaelcrosato/shardfall/blob/a9ca003/crates/pav_core/tests/motion.rs#L23-L51)). The third, decode parity within 0.001 mm against the original decoder run as an oracle, is planned in my-3dge but not yet built ([PLAN.md WP 8.2](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L3015-L3029)).

## Format, verifier and interfaces are ready; the runtime is the heavy lift

| Component | Readiness | What the repos prove | What the landscape adds | Hardest open problem |
|---|---|---|---|---|
| Canonical text format | High | Readable key poses, reused bit for bit in JavaScript and Rust | No open LLM-oriented 3D format exists; LLMs favor compact semantic codes | Real versioning, contacts and events, hands, a skeleton profile |
| Runtime: playback, blending, retargeting, IK | Medium-low | Crossfades, two-bone IK, stride matching, riftlight's foot lock | three.js lacks root motion, state graphs and reliable retargeting; JavaScript IK is thin | Retargeting onto arbitrary skinned skeletons while keeping contacts |
| Display-free inspection and verification | High | Seeded filmstrips, character sheets, fit and slide metrics | VLMs judge physics poorly; GPU-less sandboxes break canvas capture | Locomotion skating, penetration and joint limits on real meshes |
| Self-growing library | Low-medium | 325 curated clips, a 2,548-take CMU ledger, 437 clips embedded in shardfall | Clean data is scarce; one clean open generator; AI spam at Fab and ClawHub | Provenance and quality gates at scale |
| Agent interfaces | High | One registry feeding CLI, MCP and WebMCP; revisioned clip edits | MCP went stateless; Skills is portable; CLI plus skills costs fewer tokens | Being present in the context an agent actually receives |

### Make the format a self-describing standard, not a codec

Keep readable key poses as the layer agents edit, and fix what the repos exposed. Make `format` a real, validated version with written rules: optional named fields for minor versions, never longer fixed arrays, and refusal of unknown majors; my-3dge already adopted the named-field rule after shardfall's fixed-length reader forced it ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L3573-L3597)). Name the canonical skeleton after the **VRM 1.0 humanoid**, whose 15 required bones line up with the origin's 15 joints and Unity's 15-bone minimum, and ship mapping tables to Unity Humanoid, Godot, the UE Mannequin, Mixamo, Rigify and CMU/BVH ([VRM humanoid](https://raw.githubusercontent.com/vrm-c/vrm-specification/master/specification/VRMC_vrm-1.0/humanoid.md); [Unity manual](https://docs.unity.cn/Manual/UsingHumanoidChars.html)). No cross-engine humanoid standard is in practical use, and Khronos's character group chose an extension that "maps character rigs to standard vocabularies" over a fixed skeleton, warning that "establishing rigid skeletal and expression standards too early creates barriers"; its `KHR_character_skeleton_mapping` and `KHR_character_reference_pose` drafts, headed for release candidate, are the official targets to emit once ratified ([MSF 3D Assets deck, July 2026](https://metaverse-standards.org/wp-content/uploads/MSF-3D-Assets-BOF-SIGGRAPH-Jul26.pdf)). Put timing in the clip: events, contacts, root motion and stride speed for every locomotion loop, plus facts measured from motion such as shardfall's strike time. Add optional named channels for hands and face, allow tangents beside linear in-betweens (three.js r186 now serializes tangent data), and bake to glTF or VRMA at the edges from the format's parameters. my-3dge's dense bake from point-derived frames measured **0.26–0.46 mm** mean error, but 0.3–1.2% of midpoints were more than 50 mm off at singular poses and converting key for key gave outliers of 0.73 m; a bake from the parameters should remove those outliers but has not yet been measured ([three.js releases](https://github.com/mrdoob/three.js/releases); [D-mocap-library.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/docs/research/D-mocap-library.md?plain=1#L490-L514)). Keep dense samples underneath so a stronger model can drop a level. Do not adopt SMPL or SMPL-X as the canonical body, since their license bars commercial use and training for it, when Apache-2.0 alternatives such as SOMA-X and MHR exist for interchange ([SMPL-X license](https://smpl-x.is.tue.mpg.de/modellicense.html); [SOMA-X](https://github.com/NVlabs/SOMA-X); [MHR](https://github.com/facebookresearch/MHR)).

One property matters more here than it did for three.js: **no model has seen this format in pretraining.** Agents do well with Manim and Remotion partly because they write mainstream languages seen at scale, and their residual failures are invented or outdated APIs; ManiBench names "syntactic hallucinations," and Motion built its MCP server because LLMs "are trained on out-of-date information" ([ManiBench](https://arxiv.org/abs/2603.13251); [Motion docs](https://motion.dev/docs/studio-llm-documentation)). The legend in every file, a token-budgeted manual and an agent skill are the substitute for pretraining exposure, and they should version with the schema. Containers should stay trivially parseable, as plain JSON with one clip per file and no script wrappers, because shardfall needed a custom extractor for the origin's JavaScript set files ([anim_tools.rs](https://github.com/michaelcrosato/shardfall/blob/a9ca003/crates/pav_tools/src/anim_tools.rs#L17-L30)).

### Build the runtime pieces three.js never shipped

The runtime is where feasibility costs the most. three.js r186 offers a capable mixer with weights, crossfades, warps and additive clips, but no root-motion API, no state machine, and a `SkeletonUtils.retargetClip` with long-documented failures, including ignoring glTF bind matrices and twisting characters ([AnimationAction docs](https://threejs.org/docs/pages/AnimationAction.html); [three.js forum on root motion](https://discourse.threejs.org/t/looping-skinned-mesh-animation-with-root-motion/5116); [forum on retargeting](https://discourse.threejs.org/t/fixing-skeletonutils-retarget-and-retargetclip-functions/65149); [forum on twisting](https://discourse.threejs.org/t/retargetclip-twists-character/73410)). JavaScript IK is thin: three.js ships only a CCD solver, `closed-chain-ik` last published in 2023, THREE.IK calls itself a work in progress, and no maintained JavaScript foot-locking library turned up ([closed-chain-ik](https://registry.npmjs.org/closed-chain-ik); [THREE.IK](https://github.com/whatisor/THREE.IK/blob/master/README.md)). The package therefore has to supply analytic two-bone IK (which the limb encoding already parameterizes), foot locking from explicit contacts, look-at and chain IK, a declarative state graph modeled on PlayCanvas's `loadStateGraph` JSON or Bevy's `.animgraph.ron`, root-motion extraction and, above all, a retargeter ([PlayCanvas API](https://api.playcanvas.com/engine/classes/AnimComponent.html); [Bevy AnimationGraph](https://docs.rs/bevy/latest/bevy/animation/graph/struct.AnimationGraph.html)). Classical procedural layers carry no data licenses, while phase-based neural controllers, small enough for browsers at "milliseconds" and "a few megabytes," ship under research-only terms and would need retraining on clean data ([PFNN](https://theorangeduck.com/page/phase-functioned-neural-networks-character-control); [AI4Animation](https://github.com/sebastianstarke/AI4Animation)).

Retargeting is the single hardest piece. Unreal shipped automatic retargeting in 5.4, then needed a floor constraint and crotch height in 5.7 and a foot plane in 5.8, where splitting one operator broke users' setups; Babylon.js 9's new retargeter needed a snap-to-rest fix and fails on rotated meshes; and Godot users still hit T-pose versus A-pose mismatches with Mixamo clips ([Epic blog](https://www.unrealengine.com/de/blog/unreal-engine-5-4-is-now-available); [CG Channel on UE 5.7](https://www.cgchannel.com/2025/11/unreal-engine-5-7-five-key-features-for-cg-artists/); [UE 5.8 notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-8-release-notes); [UE forum](https://forums.unrealengine.com/t/ue-5-8-gasp-ikchain-retargeting-seems-broken/2732399); [Babylon.js forum on snapping](https://forum.babylonjs.com/t/after-anim-retarget-stopping-current-animation-jumps-to-rest-pose/63379); [Babylon.js forum on rotation](https://forum.babylonjs.com/t/retargeting-fails-if-avatar-mesh-is-rotated/63366); [Godot forum](https://forum.godotengine.org/t/retargeting-mixamo-animations-fails/39619)). The industry's convergence on contact constraints vindicates the origin's direction-plus-bend-plus-IK approach in principle, but no repository has done it onto arbitrary skinned skeletons, and that gap will absorb most of the engineering.

The architecture should keep the core pure, deterministic and renderer-free, split as my-3dge planned into a cheap, hashable `step` for gameplay (timelines, events, root motion) and a level-of-detail `pose` for presentation, with adapters per renderer and exporters to engine graph formats ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L941-L945)). One reference implementation plus the conformance suite beats per-engine ports. If Rust hosts like shardfall must be first-class, the Rapier analogy is literal: Rapier ships one Rust core as both the `rapier3d` crate and the `@dimforge/rapier3d` npm package, which would trade the cost of a WASM boundary for an end to rewrites ([crates.io](https://crates.io/crates/rapier3d); [npm registry](https://registry.npmjs.org/@dimforge/rapier3d)). Rapier itself supplies multibody joints and PD motors for passive ragdolls and motor-driven blending, but no balance controller, so active ragdolls stay a research add-on ([Rapier joints guide](https://rapier.rs/docs/user_guides/javascript/joints)). Motion matching and physics policies also stay out of v1: motion matching runs as WASM, but it needs dense root-motion locomotion coverage that sparse CC0 game packs are unlikely to provide, and its standard demo data, LaFAN1, is CC BY-NC-ND; physics policies train for 12 hours on four A100s at the low end and 21,000 GPU-hours for SONIC ([Motion-Matching](https://github.com/orangeduck/Motion-Matching); [ProtoMotions](https://github.com/NVlabs/ProtoMotions); [SONIC](https://arxiv.org/abs/2511.07820)).

### Verify motion with numbers first and pictures second

Display-free verification is the most feasible and most differentiated component, provided it does not depend on screenshots. Agents often run in GPU-less cloud containers, headless Linux Chrome cannot screenshot WebGPU canvases upstream, three.js's WebGPU renderer falls back to WebGL2 without an error, and riftlight measured headless Chromium losing the WebGPU device as soon as a canvas presents ([agent-browser WebGPU guide](https://agent-browser.dev/webgpu); [riftlight DOCTRINE.md](https://github.com/michaelcrosato/riftlight/blob/f3693fc/docs/DOCTRINE.md?plain=1#L115-L121)). Nor can it trust a vision model's eye: the best of 75 models scored 49.49% on PhysBench, GPT-4o managed 49.1% on which of two frames came first, and all 18 models tested on left, right, up and down performed poorly, BLIP-VQAv2 scoring 56% against 99% for humans ([PhysBench](https://arxiv.org/pdf/2501.16411); [TemporalVQA](https://arxiv.org/abs/2501.10674v2); [What'sUp](https://arxiv.org/abs/2310.19785)). These are 2025-era models and current ones are likely better, but newer motion benchmarks already compute foot sliding and penetration geometrically rather than by VLM ([MBench](https://arxiv.org/pdf/2510.26794)).

The core loop should compute metrics straight from skeleton data: foot skate during detected contacts (Kimodo's paper offers calibration, **3.87 cm/s generated against 2.21 cm/s for real capture**), ground penetration and floating, jitter and jerk, pops, joint limits, bone stretch, loop seams, stride against root speed, retarget end-effector error, and hit timing against motion peaks ([Kimodo paper](https://arxiv.org/html/2603.15546v1)). Baselines should list accepted exceptions and fail when one worsens, as my-3dge specified ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L1330-L1355)), and a predicate language in MoVer's spirit ("left foot planted 0.33–0.60 s, slide under 1 cm") turns failed checks into repair instructions. Pictures come second, as labeled contact sheets rather than frame sequences: a 1000×1000 image costs Claude 1,296 tokens, animated GIFs are read as their first frame only, and Gemini samples video at 1 fps by default, too coarse for a gait ([Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision); [Gemini video docs](https://ai.google.dev/gemini-api/docs/video-understanding)). Two optional checks can plug in later. A physics tracker works as a feasibility filter: choosing among eight generated candidates by how well SONIC tracked them raised upright execution from **80.5% to 89.5%**, where a kinematic fall predictor recovered only a quarter of that gain ([S³](https://arxiv.org/abs/2609.26420)). Learned critics belong only in ranking: MotionCritic matches human preference 85% of the time, yet fine-tuning a generator against it for 700 steps degraded the generator ([MotionCritic](https://arxiv.org/html/2407.02272v2)).

### Ship a CLI and skills first, and a thin MCP second

Interface evidence favors layers. Playwright's own MCP README says coding agents "might benefit from using the CLI+SKILLS instead" to avoid loading large tool schemas, and Anthropic's guidance favors a few consolidated tools with concise and detailed output modes ([Playwright MCP](https://github.com/microsoft/playwright-mcp); [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)). Agent Skills is the most portable carrier of "how to animate with this," with 46 listed clients and 180k stars on the reference repository, and MCP's 2026-07-28 revision suits an animation API: stateless requests, "explicit, server-minted handles passed as ordinary tool arguments" (a `clip_id`, a `rig_id`), deterministic tool ordering for prompt caching, and a tasks extension for long renders ([agentskills.io](https://agentskills.io); [MCP changelog](https://modelcontextprotocol.io/specification/latest/changelog)). Depthward's registry, riftlight's six-step tool template ([riftlight ENGINE.md](https://github.com/michaelcrosato/riftlight/blob/f3693fc/docs/ENGINE.md?plain=1#L1493-L1518)) and shardfall's revisioned edits are ready-made patterns; what is missing is the domain vocabulary of search, inspect, edit, render, check, retarget-preview and contribute. Two lessons should become acceptance gates: the tools must ship inside whatever artifact an agent is handed, and a fresh agent must complete tasks cold, as in shardfall's dry run, where another model listed 13 friction points, among them silently ignored unknown arguments ([shardfall HISTORY.md](https://github.com/michaelcrosato/shardfall/blob/a9ca003/docs/HISTORY.md?plain=1#L794-L800)). llms.txt is cheap, but 97% of such files got zero requests in May 2026, and WebMCP is still a Chrome origin trial whose API has already changed shape, so both are conveniences rather than foundations ([PPC Land](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/); [Chrome blog](https://developer.chrome.com/blog/ai-webmcp-origin-trial); [WebMCP draft](https://webmachinelearning.github.io/webmcp/)).

## The self-growing library is the weakest leg

| Source | What it holds | Terms | Usable in an open, editable, shippable library? |
|---|---|---|---|
| Quaternius UAL 1 and 2 | 120+ and 110–130 game clips; UAL2 v2.2 dated 28 September 2026 | CC0 ([UAL1](https://quaternius.com/packs/universalanimationlibrary.html), [UAL2](https://quaternius.itch.io/universal-animation-library-2)) | Yes |
| Mesh2Motion | Bundled rigs and clips | CC0 per its README; press reports CC-SA and CC-BY on some models ([README](https://github.com/Mesh2Motion/mesh2motion-app), [CGWorld](https://cgworld.jp/flashnews/01-202608-Mesh2Motion.html)) | Yes, after a per-asset audit |
| Kenney | A handful of clips | CC0 ([Kenney](https://kenney.nl/support)) | Yes, but tiny |
| 100STYLE | 100 locomotion styles, over 4M frames at 60 fps | CC BY 4.0 ([100STYLE](https://www.ianxmason.com/100style/)) | Yes, with attribution |
| CMU MoCap | 2,548 takes in the predecessor's ledger | Free in products, but no resale "even in converted form" ([CMU notice via 4TU](https://data.4tu.nl/datasets/0448aab2-3332-449f-a8e2-d208cb58c7df/1)) | In shipped games, yes; never relicensed as CC0 or MIT |
| AMASS and derivatives, MotionMillion, OpenT2M | 40 to 2,800+ hours | Non-commercial or no license ([AMASS](https://amass.is.tue.mpg.de/license.html), [MotionMillion](https://huggingface.co/datasets/InternRobotics/MotionMillion), [OpenT2M](https://arxiv.org/html/2603.18623)) | No |
| LAFAN1, Bandai Namco | 4.6 hours; about 420k frames | CC BY-NC-ND; CC BY-NC ([LAFAN1](https://raw.githubusercontent.com/ubisoft/ubisoft-laforge-animation-dataset/master/license.txt), [Bandai Namco](https://github.com/BandaiNamcoResearchInc/Bandai-Namco-Research-Motiondataset)) | No |
| Mixamo, Ready Player Me | Vendor clip libraries | Use in products; no redistribution of files ([Mixamo FAQ](https://community.adobe.com/questions-696/mixamo-faq-licensing-royalties-ownership-eula-and-tos-589400), [RPM license](https://raw.githubusercontent.com/readyplayerme/animation-library/master/LICENSE.md)) | No |

Only two sizeable capture corpora survive the filter, 100STYLE (locomotion only) and CMU (resale-restricted), while everything at the scale modern models train on is non-commercial or unlicensed. That forces per-clip licensing: CMU-derived clips need their own namespace carrying CMU's notice, 100STYLE clips need attribution, and Quaternius and Kenney clips can be CC0. It also exposes repairs the predecessor owes: the CMU record, a re-check of imports against Quaternius's UAL2 v2.2 update of 28 September 2026, and a Mesh2Motion audit after conflicting license reports. "Extensive" cannot come from imports alone. The curated cores across the repos run to hundreds of clips, with 325 in the origin and 1,218 planned in my-3dge, and the dense locomotion coverage that motion matching needs would have to come from 100STYLE, new capture or synthesis rather than the CC0 game packs ([PLAN.md](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L3540)).

Generation scales the library, but narrowly and through one vendor. Nearly every academic text-to-motion model trains on HumanML3D, which is built from AMASS, whose license forbids training "for commercial use of any kind" ([AMASS license](https://github.com/nghorbani/amass/blob/master/LICENSE.txt)). Tencent's HY-Motion, the strongest model by its own evaluation, "DOES NOT APPLY IN THE EUROPEAN UNION, UNITED KINGDOM AND SOUTH KOREA," requires a separate license above 1 million monthly users, and bars using outputs "to improve any other AI model," terms incompatible with a global library others will train on ([HY-Motion license](https://github.com/Tencent-Hunyuan/HY-Motion-1.0/blob/master/License.txt)). Kimodo is the one clean open option, and a qualified one: trained on Bones Studio capture that NVIDIA's README calls "commercially-friendly" and its model card calls "proprietary," governed by a license NVIDIA "may update… at any time," realistic-only, capped at 10 seconds a clip, admittedly prone to foot skating, and needing about 17 GB of VRAM unless its text encoder moves to the CPU ([Kimodo README](https://github.com/nv-tlabs/kimodo); [Kimodo SOMA-RP card](https://huggingface.co/nvidia/Kimodo-SOMA-RP-v1.1); [NVIDIA Open Model License](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-open-model-license/); [SOMA-SEED card](https://huggingface.co/nvidia/Kimodo-SOMA-SEED-v1.1)). The best learned in-betweeners cut SLERP's position error by about two-thirds at 30-frame gaps but train on LaFAN1 or AMASS, and video capture is no cleaner, since the leading world-grounded method, GVHMR, is research-only and Meta's commercially usable SAM 3D Body takes "several seconds per image" ([SILK](https://arxiv.org/html/2506.09075v1); [GVHMR license](https://github.com/zju3dv/GVHMR/blob/main/LICENSE); [Fast SAM 3D Body](https://arxiv.org/abs/2603.15603)). Commercial APIs are cheap, since seeding 1,000 five-second clips through Uthana would cost roughly $100 to $500, and Uthana's paid outputs belong to the user while its free-tier outputs, if that tier survived the August pricing change, are CC BY 4.0; but Mixamo and DeepMotion forbid redistributing exactly the editable files a library needs ([Uthana pricing](https://uthana.com/pricing); [Uthana terms](https://uthana.com/terms); [DeepMotion terms](https://www.deepmotion.com/terms-of-use)). **Price is not the barrier; license and quality are.**

US law makes the AI-generated part of a library free to share and impossible to own. The Copyright Office concluded that "prompts do not alone provide sufficient control" and that purely AI-generated material is unprotected, and the Supreme Court denied review in *Thaler v. Perlmutter* on March 2, 2026 ([USCO Part 2](https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf); [SCOTUSblog](https://www.scotusblog.com/cases/case-files/thaler-v-perlmutter)). Ordinary movement carries thin copyright anyway, as the Office treats "ordinary motor activities" as unregistrable, so dataset licensors' leverage is mainly contractual and the danger zone is choreography, where the Ninth Circuit let a claim against Epic Games proceed ([Compendium ch. 800](https://www.copyright.gov/comp3/chap800/ch800-performing-arts.pdf); [Lewis Silkin on *Hanagami v. Epic*](https://www.lewissilkin.com/insights/2024/01/22/the-battle-continues-for-epic-games-and-hanagami-developers-beware-a-new-copyrig-102ixp7)). Labeling is the open question. The EU AI Act's marking duty applies from August 2, 2026 (December 2, 2026 for systems already on the market) but names audio, image, video and text, not motion; Steam requires disclosure of shipped AI assets, and Fab requires a "CreatedWithAI" tag ([AI Act Art. 50](https://artificialintelligenceact.eu/article/50/); [Garrigues](https://www.garrigues.com/en_GB/garrigues-digital/ai-digital-omnibus-regulation-has-been-published-redefining-deadlines-and); [tbreak](https://tbreak.com/steam-ai-disclosure-policy-update-developers/); [UE forum](https://forums.unrealengine.com/t/ai-image-use/2567909)). The prudent design records a per-clip `digitalSourceType` from the IPTC vocabulary and requires a CC0 dedication from every contributor ([IPTC](https://cv.iptc.org/newscodes/digitalsourcetype/)).

Every precedent for AI-fed open catalogs warns against an open door. One seller pushed 38,000 to 41,000 AI assets onto Fab in May 2025; ClawHub's agent-skill registry carried 341 malicious skills, some padding READMEs to 22 MB to slip past scanners; curl ended its bug bounty after a flood of AI-generated reports; and an agent, or its operator, answered a rejected matplotlib pull request by publishing a hit piece on the maintainer ([80.lv](https://80.lv/articles/epic-games-adresses-ai-generated-content-plaguing-fab); [Unit 42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain/); [The Register on curl](https://www.theregister.com/2026/01/21/curl_ends_bug_bounty/); [The Register on matplotlib](https://www.theregister.com/2026/02/12/ai_bot_developer_rejected_pull_request)). The catalogs with consistent quality are single-author (Kenney, Quaternius) or contract-vetted, like Poly Haven, which bans generative AI "at any stage" ([Poly Haven](https://polyhaven.com/contribute)). The workable model pairs a curated core with a federated, namespace-verified index for community packs. The core admits clips through schema, physical-metric, retarget-to-reference-rig and license-allow-list gates, a declared training-data manifest for any generator, an accountable human behind every agent, rate limits, no per-clip rewards and a human merge; both tiers borrow package-registry mechanics such as immutable versions, yank instead of delete, trusted publishing and signed provenance ([npm unpublish policy](https://docs.npmjs.com/policies/unpublish); [Cargo publishing](https://doc.rust-lang.org/cargo/reference/publishing.html); [MCP Registry](https://modelcontextprotocol.io/registry/about)). Clips are inert data, which sidesteps the worst malware class, but the skills, MCP server and importers the package ships carry ClawHub-style supply-chain risk and need signed releases from the first version. No motion-specific provenance standard exists, since C2PA's reference library supports no glTF, USD or JSON, so per-clip SPDX identifiers via REUSE, parent-clip content hashes and generator manifests are the practical stack ([c2pa-rs formats](https://github.com/contentauth/c2pa-rs/blob/main/docs/supported-formats.md); [REUSE 3.3](https://reuse.software/spec-3.3/)).

## Be the airframe and the test range, never the pilot

The positive case is specific. The package should own the layer no one else owns and treat everyone above it as a supplier: a generator socket takes intent and constraints in and returns a clip in the format, with model, version and license recorded, through the same gates as any import. The readable format suits that socket unusually well, because Kimodo is steered by frame-indexed joint positions, rotations, headings and root paths with **2.67 cm** full-body keyframe error, so an agent can write three to ten key poses, let the model fill the frames, and have the verifier check the result against the keys it wrote ([Kimodo paper](https://arxiv.org/html/2603.15546v1); [Kimodo G1-SEED card](https://huggingface.co/nvidia/Kimodo-G1-SEED-v1)). NVIDIA's real-time successors, ARDY (July 2026) and MotionBricks (a claimed 2 ms), fit the same socket ([ARDY](https://research.nvidia.com/labs/sil/projects/ardy/); [MotionBricks](https://nvlabs.github.io/motionbricks/)). Web-first delivery is uncontested, since every vendor profiled targets Unity, Unreal, Maya, Blender or a hosted editor, though demand among web developers has not been measured. And framing matters: with 52% of game developers calling generative AI bad for the industry, and 64% in visual and technical art, the package should present itself as correctness, verification and provenance tooling rather than a replacement for animators ([GDC 2026](https://gdconf.com/article/gdc-2026-state-of-the-game-industry-reveals-impact-of-layoffs-generative-ai-and-more/)).

| Be | Do not be | Why |
|---|---|---|
| A versioned spec with curated, licensed data and a conformance suite | Another text-to-motion model | Tripo alone raised about $800M in 2026; NVIDIA, Tencent, Epic, Autodesk and Uthana already compete on models |
| A deterministic runtime with renderer adapters and exports to glTF, VRMA and engine graphs | A replacement for Unreal's or Unity's animation systems | Users inside those engines get motion matching, Control Rig and Unity AI built in |
| A display-free verifier that reports metrics and labeled sheets | A GUI editor or a video-capture service | Cascadeur now ships an MCP server, Maya lets users train custom MotionMaker models, and Rokoko and Move.ai own capture ([CG Channel](https://www.cgchannel.com/?p=177897); [CG Channel](https://www.cgchannel.com/2026/07/maya-2027-2-lets-you-train-your-own-ai-animation-models/)) |
| A curated core plus a namespace-verified index | An open upload portal | Fab and ClawHub were flooded within months |
| A canonical bone vocabulary with mapping tables | A mandated skeleton, or an SMPL-based body | No cross-engine standard is in use; SMPL licenses bar commercial use |
| A generator socket that records license and model per clip | Dependent on one vendor's model terms | NVIDIA reserves the right to change its license; Uthana repriced in 2026 and DeepMotion narrowed its API to partners |
| Engine-neutral motion | A carrier of the origin's pixel-art machinery | Sprite ticks, eight-way facing and the chibi rig are game choices, not animation |

Ranked by how hard each is to undo, the risks run in this order. **Library contamination comes first**, because a clip with tainted provenance propagates into shipped games and cannot be recalled, and the predecessor's CMU error shows how easily that happens even to careful authors. **Retargeting quality comes second**, since it decides whether "any humanoid" is true, and the engines that solved it took several releases and still break users' setups. **Adoption comes third**, and it has two faces. Agents ignore what is not in their context, as the Vesper build showed, and incumbents hold most of the pieces: Epic has an MCP plugin, MetaHuman, Meshcapade's team and a precedent of MIT-licensing RigLogic; NVIDIA has Kimodo, the SOMA skeleton and open model licenses; and Unity already bundles Uthana ([GamesBeat](https://gamesbeat.com/epic-games-launches-unreal-engine-5-8/); [SOMA-X](https://github.com/NVlabs/SOMA-X)). Attention will not settle it either. three.js has 116k stars and 20.5 million weekly npm downloads, but Theatre.js has 12.7k stars, about 18.7k weekly downloads and no public push since 2024, and Motion Canvas has 19.3k stars and 5.5k weekly downloads; maintenance and agent tooling track real use better than stars ([three.js stars](https://ungh.cc/repos/mrdoob/three.js); [three.js downloads](https://api.npmjs.org/downloads/point/last-week/three); [Theatre.js](https://ungh.cc/repos/theatre-js/theatre); [Theatre.js downloads](https://api.npmjs.org/downloads/point/last-week/@theatre/core); [Motion Canvas](https://ungh.cc/repos/motion-canvas/motion-canvas); [Motion Canvas downloads](https://api.npmjs.org/downloads/point/last-week/@motion-canvas/core)). **Execution comes fourth**, and the repos' own history is the warning: in my-3dge, every work package that reported its size overran the plan by one class and nine ADRs collected 22 amendments in two days, while the origin's two engine editions shipped a feature in one edition well before the other ([PLAN.md ledger](https://github.com/michaelcrosato/my-3dge/blob/652ea6b/PLAN.md?plain=1#L3917-L4040); [ADRs](https://github.com/michaelcrosato/my-3dge/tree/652ea6b/docs/decisions); [CHANGELOG](https://github.com/michaelcrosato/my-3d2dge/blob/14a561c/CHANGELOG.md?plain=1#L55)). The structural remedy is to make this package the upstream that engines pin rather than another sibling they port. **Blind or gamed metrics come last**, as MotionCritic's over-optimization and the origin's idle-only slide check show, so every gate needs human sampling and an adversarial review of what it fails to see.

## Conclusion

The three.js and Rapier analogy is only half right. Those libraries ship code and no content; their users bring the assets and the judgment. The evidence here inverts that. Across five repositories the code was rewritten each time while the format, data and golden vectors traveled intact, and the scarce, defensible assets in the 2026 landscape are clean motion data and trustworthy checks, not playback code. The package is closer to glTF plus Poly Haven plus a test suite, with a three.js-like runtime as its reference implementation, which makes its first engineering deliverable governance (schema versioning, provenance, gates and conformance) rather than features. Distribution inverts as well. Agents use what sits in their context, so a legend in every file, a skill and a 35-token catalog line do the work that marketing does for libraries humans choose, and the Vesper build, which used none of 325 clips that sat in the same repository but outside the file it was handed, is the single most decision-relevant data point in this study.

The order of work follows from the evidence. The cheapest, most proven and most differentiated parts come first: the format specification, the display-free verifier and the CLI with its skill, together with the benchmark nobody has built yet, frontier models editing skeletal keyframes under numeric checks, which would serve as the package's acceptance test and, as far as this study found, as a first for the field. The retargeting core comes second, and library growth third, at the pace clean generators and human-backed gates allow rather than the pace agents can produce clips. The window is real but not permanent. Khronos's character extensions are moving toward release candidate, and Epic and NVIDIA each hold most of the pieces for an open motion stack of their own, which argues for building on the KHR_character vocabularies rather than against them, and for publishing the standard before an incumbent defines it.
